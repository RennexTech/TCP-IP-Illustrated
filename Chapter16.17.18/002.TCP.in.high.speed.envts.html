HighSpeed TCP Response Function

Standard TCP performs poorly on high-speed WANs because window growth is too linear. HSTCP modifies the relationship between window size (w) and drop rate (p) using a Power Law function when w > Low_Window.

w = C • pS
Where constant C = P0-S W0
w = Window Size
p = Packet Drop Rate
S = Slope (on log-log plot)
W0, P0 = Anchor Points
📈

Generalized AIMD Updates

Instead of fixed constants (add 1, halve window), HSTCP makes the increase (a) and decrease (b) parameters dynamic functions of the current window size.

On Good ACK (Increase)
cwndt+1 = cwndt +
a(cwndt) cwndt
On Congestion Event (Decrease)
cwndt+1 = cwndt - ( b(cwndt) • cwndt )

Limited Slow Start Algorithm

To prevent massive packet bursts when window sizes are huge (tens of thousands of packets), we introduce max_ssthresh to brake the exponential growth.

if (cwnd <= max_ssthresh) { // Standard Exponential Growth cwnd = cwnd + SMSS } else { // Limited Growth (Linear-ish) K = int(cwnd / (0.5 * max_ssthresh)) cwnd = cwnd + int( (1/K) * SMSS ) }
max_ssthresh = Threshold (typ. 100 pkts)
K = Dampening Factor
SMSS = Max Segment Size
