The CUBIC Growth Function

CUBIC replaces the linear growth of standard TCP with a cubic function. This creates a curve that is concave (cautious) when below the saturation point and convex (aggressive) when above it.

W(t) = C(t - K)3 + Wmax
W(t) = Window Size at time t
C = Scaling Constant (0.4)
t = Time since last loss
Wmax = Window size before loss
⏱️

Calculating K (Target Time)

K represents the time it takes for the window to grow back to Wmax after a loss event.

K = ∛
Wmax • β C
β = Decrease Factor (0.2)
C = Cubic Constant (0.4)
📈

Growth Phases & Features

🐢
Concave Phase (W < Wmax) When recovering from loss, growth slows down as it approaches the previous saturation point to avoid overshooting.
🚀
Convex Phase (W > Wmax) Once Wmax is exceeded without loss, CUBIC assumes bandwidth is available and accelerates growth (Max Probing).
🤝
TCP Friendliness In small windows (low BDP), CUBIC mimics standard Reno to ensure it doesn't starve legacy connections.
🐧

Linux Kernel Implementation

Default since kernel 2.6.18. Managed via sysctl.

net.ipv4.tcp_congestion_control = cubic
net.ipv4.tcp_allowed_congestion_control = cubic reno
