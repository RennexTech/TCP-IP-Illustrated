CIDR Aggregation Calculation

This page explains how we aggregate multiple smaller IP address blocks into a larger network using CIDR notation. We’ll take the following networks:

  • 192.168.1.0/24
  • 192.168.2.0/24
  • 192.168.3.0/24
  • 192.168.4.0/24

Step-by-Step Calculation

1. Convert to Binary

First, convert the IP addresses of each network to binary format:

192.168.1.0 -> 11000000.10101000.00000001.00000000
192.168.2.0 -> 11000000.10101000.00000010.00000000
192.168.3.0 -> 11000000.10101000.00000011.00000000
192.168.4.0 -> 11000000.10101000.00000100.00000000

Notice that the first 22 bits are common for all the addresses. This indicates that the first 22 bits can be used for the new aggregated network.

2. Find the Common Network Prefix

The first 22 bits of each of these addresses are identical. So, the aggregated network will have a `/22` prefix. This means we combine these four `/24` networks into a single `/22` network.

3. Aggregated Network

The aggregated network address is:

192.168.0.0/22

The subnet mask for this network is 255.255.252.0. This gives us the new range from 192.168.0.0 to 192.168.3.255, which encompasses all the original subnets.

Conclusion

By applying CIDR aggregation, we’ve reduced four entries in the routing table (one for each /24 network) into a single entry for the 192.168.0.0/22 network. This helps to reduce the size of the global routing table and improves routing efficiency.

Summary:

  • Original networks: 192.168.1.0/24, 192.168.2.0/24, 192.168.3.0/24, 192.168.4.0/24
  • Aggregated network: 192.168.0.0/22
  • Subnet Mask for /22: 255.255.252.0
